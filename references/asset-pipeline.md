# 像素素材契约与制作取舍

用于批量素材、动画及地图资产；不要将示例规格硬套在已有工程中。

## 最小契约

每个素材记录：稳定 ID、用途、画布尺寸／图集格子、调色板、透视、源文件与输出路径。动画追加方向顺序、每段帧数、FPS、循环与脚底锚点；图块追加可重复方向、过渡／边缘规则；作物追加地面占位、生长阶段和高度。

随附样板的实际契约位于 `assets/farm-template/assets/manifest.json`：

- 环境图集 256×128，基础格 16×16。
- 农夫图集 192×256，格子 32×32，方向顺序下／上／左／右。
- 第 0–3 行每方向 4 帧待机，第 4–7 行每方向 6 帧移动；共 40 帧。
- 脚底锚点 (16,29)，运行按 2 倍绘制；窗口缩放不改变源尺寸。
- 作物帧 16×32，地面占位 16×16；演示每 2.5 秒推进一阶段，仅用于加速展示。

## 生成器重用

`assets/farm-template/generators/draw-assets.mjs` 为可运行的确定性栅格绘制示例，使用矩形、椭圆、多边形和线段生成调色板索引数据。复制到新工程后，在该工程中修改。

运行时只输出到其所在工程的 `source/`，不会直接覆盖 PNG 或 Pixelorama 工程。生成后的 JSON 含 `width`、`height`、`palette`、`rows`；每格字符的 Unicode 值减 65 即为颜色索引。JSON 文件可避免模型反复读取长像素数组。

通过 Pixelorama 的 `eval_gdscript` 把颜色数据写入图像，预览后再保存 `.pxo` 和导出。参见 MCP 调用参考。需要保留手工修整时，从现有 `.pxo` 导出，而不是重新生成后覆盖。

## 视觉与功能验收分开

完整场景的布局、HUD 与视觉检查见 [visual-direction.md](visual-direction.md)。批量生成前将代表性资产放进实际场景验收比例、轮廓、接地和视觉主次；确定性绘制只保证可复现，不能自动代表素材达到游戏美术表现要求。

尺寸、透明边界、帧数、颜色数、图块接缝可程序检查，但“透明洞”也可能是设计，不能一律自动填充。轮廓可读性、动画重量感、风格一致性需要看图。

需要可重复的静态检查时，使用 [asset-qa.md](asset-qa.md) 中的契约与脚本。当前脚本覆盖尺寸、透明度、声明调色板和动画帧，并输出复核提示；地形接缝仍使用拼接预览与真实场景检查。记录素材来源／生成方式及适用授权，手工修整后以可编辑源工程为准导出并重新检查。

种田游戏特别检查：人物脚底是否漂移，作物／树冠遮挡是否符合脚底顺序，成熟阶段是否清晰，干湿土是否能区分，农田操作范围是否符合画面。游戏内原比例预览优先于单张放大截图。

地形边缘、导航和碰撞需要实际规则或资源配置。样板的四种草地是变化纹理，并非已经实现自动地形过渡；不要通过批量导出 PNG 就宣称地图系统完成。

## 生图、后处理与精修的取舍

新美术优先按 [generated-art-pipeline.md](generated-art-pipeline.md) 使用内置生图及其低成本批量策略；确定性脚本适合规则图块、参数变体和标准化，Pixelorama 负责精修。候选不能仅凭像素风外观直接交付。静态道具可小批次排成素材板；简单角色可在一张板中分行试作，各角色、方向与动作保持独立分组，复杂角色按需要单独制作；地形单独验证接缝。复杂整图不应默认能通过少量修整成为合格素材。

从代表性资产实测候选数量、编辑耗时、模型用量及接口费用。每件验收成本以成功交付数为分母；订阅用量没有可靠折算时单独报告，不固定服务商价格。
