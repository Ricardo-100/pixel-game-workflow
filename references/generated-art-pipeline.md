# 内置生图素材板到游戏图集

## 制作与选择

遵循 imagegen 技能，默认调用内置 `image_gen`，透明素材设置 `transparent_background=true`。先生成再复制实际返回的文件到工程；不假设工具可指定输出路径。不需要 API key，不自动购买或配置外部服务。

一张素材板作为一次图像交付：明确主体、风格、视角、布局、动作顺序、留白和真实透明背景。静态道具按相关小组生成；动画按角色／方向／动作分组，同一张素材板可包含多个明确分离的角色组。用已有参考图保持风格，不能凭文字承诺逐帧一致。不要请求文字标签或可见格线。原图、提示词和候选选择保留在工程 source 目录。

先看图：缺件、遮挡、角色身份变化、假透明棋盘格或错误动作需要回到生图。小幅边缘与个别像素问题可留给 Pixelorama。不要默认均分图像就能正确切帧；按实测边界确认区域。

## 低成本批量策略

- 风格、视角与目标尺寸一致的简单角色，优先从一张“2 个角色 × 各 4 帧”素材板试作。每行一个角色，每列是该角色明确指定的动作姿态；四帧是已验证的起点，不替代玩法实际需要的帧数。
- 同一角色的帧保持独立切分契约与共享缩放，分别输出图集、`.pxo` 和动画配置。不同角色按游戏比例选择各自的共享缩放；不能逐帧自动 fit，也不能将两行串成同一个角色的八帧动画。
- 复杂人形、装备细节、复杂动作或大尺寸角色优先单独生成。扩大到四个及以上角色前先试作，不将双角色结果视为更大批次的可靠性证明。
- 只需换色的变体复用合格基础动画，用明确的颜色映射脚本处理并复核，不重复生图。切分、对齐和打包用脚本；Pixelorama 只修局部可见问题，无需精修时直接保存导出。
- 保留已验收角色，只补生成失败角色，必要时引用原素材板保持风格；不为局部失败重做整批。与主流程共用重试上限，出现大量重绘需求时缩小批次或调整规格。
- 以“生成、重试、处理、精修的实际消耗 ÷ 合格角色或素材数量”比较方案；分别记录调用次数、耗时与可见用量。减少生图调用不能直接等同于减少账单，Pixelorama 每角色的保存与验收仍需执行。

已验证范围（2026-10-16）：单次内置生图约 44 秒，生成史莱姆、蘑菇各四帧；整理为 64×64 后，8/8 帧达到简单待机原型可用标准，无重生成或手工补像素，Pixelorama 导出与可见像素一致，Godot 实际播放两组全部帧。与此前单角色四帧样本相比，总输出像素均约 157 万，每角色生图调用由 1 次降至 0.5 次；这是单次历史样本比较，不证明费用减半或全局最低成本。两样本均未达到严格限色像素美术标准；复杂人物、四向行走、四角色批次、静态道具批次数量与无缝地形未由本测试验证。

## 可复现的整理

`scripts/prepare_sheet.py` 需要 Pillow，读取 PNG 与明确契约，输出单帧 PNG、横排 sheet.png、4 倍预览、GIF 和 processing.json。只创建新输出目录，不覆盖已有版本。GIF 仅用于预览，RGBA PNG 为正式素材。

契约示例（坐标为原图像素，pivot 相对于该 rect）：

```json
{
  "frame_size": [64, 64],
  "anchor": [32, 60],
  "scale": 0.125,
  "duration_ms": 160,
  "regions": [
    {"id": "idle-0", "rect": [0, 0, 512, 768]},
    {"id": "idle-1", "rect": [512, 0, 512, 768]}
  ]
}
```

调用：`python SKILL_DIR/scripts/prepare_sheet.py --source PROJECT/source/candidate.png --contract PROJECT/source/slicing.json --output PROJECT/processed/v1`。

- 同组共享 scale，不能逐帧独立 fit；超出画布报错，调整规格后重跑。
- 默认用可见包围盒底部中心对齐，适合接地待机。跳跃、武器、投射物等必须指定人工确认的 pivot，以免抵消有意位移。背景残点会污染包围盒，先检查。
- 默认保留 alpha；只有契约明确要求硬边时设置 `alpha_threshold`（1–255）转二值透明。不得用全局删白代替抠图。
- 最近邻缩放只保证采样方式，不能自动恢复真正像素网格；缩小后仍需目检轮廓和细节。
- 此脚本不自动量化颜色、不推断动画语义、不补帧，也不生成地形连接。需要调色板收敛时在候选副本上明确执行并复核。

## Pixelorama 精修与最终导出

先检查已有画布，创建本次专用画布。静态图 `import_image` 显式 `remove_background=false`；动画先创建最终单帧尺寸画布，再 `import_spritesheet` 指定帧宽高和帧数。导入后核对帧数、空帧、顺序、alpha 和画布大小，不能只检查工具成功。

局部修正可批量提交，保存 `.pxo` 后导出原尺寸 PNG。PNG 导入只能获得栅格层，不能声称恢复了原始分层。重开 `.pxo` 验证可编辑帧仍存在；比较导出与预期，必要时检查逐像素差异，防止错误去背景或丢帧。比较时把 alpha 为零的 RGB 值规范化或忽略：导出可能清零不可见 RGB，不能把这类差异误报成可见像素损坏。

若需要大量重绘，重新生成或拆小批次。手工修整后的 `.pxo` 是后续导出的依据，不再用旧处理输出覆盖。

## 验收边界

运行现有 audit_assets.py，结合逐帧接触表、循环预览和 Godot 实际运行检查。静态道具、动画与地形各自给结论；一个待机动画成功不能证明四向行走、无缝地形或批量多类素材都可靠。记录生图调用次数、后处理与精修操作、失败原因和未验证项目，账单不可见时费用记未知。
