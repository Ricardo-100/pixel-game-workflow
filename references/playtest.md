# 可复现试玩与证据

用于完整 Demo、交互修改和运行问题复现。连接、会话、Godot AI 工具示例见 [mcp-recipes.md](mcp-recipes.md)，视觉检查见 [visual-direction.md](visual-direction.md)。先发现当前工具能力，不将其他 Godot MCP 的函数名直接套进 Godot AI。

## 三种检查各自证明什么

| 检查 | 可以证明 | 不能据此推出 |
|---|---|---|
| 解析／无界面启动 | 指定入口能够加载，采样期间记录的错误 | 操作有效、画面正常；存活游戏的预期超时也不是崩溃证据 |
| 规则方法检查 | 规则、失败分支、资源变化及临时状态恢复 | 键位／鼠标、输入焦点、信号和真实碰撞链路有效 |
| 实际输入试玩 | 输入经过绑定与场景交互到达可观察结果 | 未覆盖的全部玩法或其他平台都正常 |

素材静态检查和以上检查均不能替代视觉判断。按任务范围选检查，不为单张 PNG 修改运行整套游戏。

## 选择短而完整的操作链

在已有报告写一条正常流程和相关失败路径，每条记录起始条件、实际输入、等待条件、预期状态、实际状态与证据。例如种田小样：

| 情形 | 起始条件与操作 | 可观察结果 |
|---|---|---|
| 正常流程 | 从指定位置移动到空地，按项目已绑定操作播种、浇水；等待成熟，再收获 | 玩家位置改变；地块与作物外观逐步变化；种子／奖励按规则增减 |
| 距离失败 | 站在范围外对相同对象执行操作 | 拒绝且资源与对象状态保持合理；给出可辨反馈 |
| 状态失败 | 对未成熟作物收获，或资源耗尽后再操作 | 不提前发奖、不出现负资源；反馈与规则一致 |
| 面板与碰撞 | 打开并关闭主要面板，再移动；尝试穿过已定义障碍 | 关闭后输入恢复；被声明为障碍的对象阻止通行 |

只覆盖工程真实存在的机制。没有完整背包、地形碰撞或存档时，标为未实现，不伪造测试。复现关键交互即可，不默认随机压力测试。

## 实际执行

1. 核对项目路径、场景和本次运行身份。先读已有运行状态；用户正在玩的进度优先保留，可用独立验收场景或临时状态快照。快照应涵盖本次会改变的资源、计时器和玩家位置；会写存档时使用隔离测试存档。
2. 从项目 InputMap 和 UI 信号确定真实输入。有运行输入工具时发送已存在的 action 或点击；键位映射修改还需要实际按键路径。所有按住的输入都在结束或异常清理时释放。
3. 等待可观察条件和合理截止时间，例如对象状态变为成熟、面板出现；超时记录最后状态，读取当前日志。避免仅凭固定睡眠时长假定操作已完成。
4. 读取前后位置／资源／对象状态，保留实际输入步骤及对应截图。直接赋值资源或调用规则方法可用于准备独立测试状态，必须写明；不能将其记为输入成功。加速时间的测试也单独注明。
5. 交互画面截在动作过程中；瞬时动作使用连续帧。确认截图来自本次游戏帧，排除过期截图、编辑视口和其他实例。
6. 读取本次启动以来的新增日志；支持游标时记录游标，否则记录采样时间与旧错误背景。保留错误信息，修复后只复测受影响流程；不清日志伪造通过。
7. 释放输入，恢复测试状态；只停止本次启动的验收实例。没有可靠恢复方法时另建独立测试场景，避免在用户进行中的存档试验。

缺少自动输入时，可用已授权的界面工具完成，或给用户可复现步骤并将输入试玩标为未验证。运行助手不在线时可以检查加载和规则，但不能冒称完成真实试玩。工具连续失败后记录错误与限制，继续独立部分，不无限恢复或自动更换整套 MCP。

## 报告要点

复用项目已有报告目录；记录目标工程／场景、引擎与插件版本（能查到的）、时间、素材检查报告或哈希、每条用例的步骤／预期／实际／结论、截图路径及剩余问题。素材技术、输入试玩、视觉分别标为通过／未通过／未验证；不适用项目写明原因。旧图和旧日志作为背景保留，不计入本次通过证据。

截图差异只在同分辨率、相同相机／状态、可控随机种子和时间的条件下有意义；动态区域可排除或给合理容差。不要对正常水面动画强求零像素差，也不要将基线更新当成修复。
